Abstract

This project aims to detect fraud messages in conversations with a bank chatbot. We use the Banking77 dataset from PolyAI, which contains 13,083 customer messages labeled with 77 intents, together with a message stream simulated from its training split. An extract, transform, and load (ETL) process cleans the text, builds an intent catalog, and stores date-partitioned Parquet data for processing in Amazon S3 and Apache Spark. We use natural language processing and machine learning to classify message intent and investigate text and behavior signals for fraud detection. The completed experiments achieve 89.06% intent accuracy with a scikit-learn model and 84.45% with a Spark MLlib model on the held-out Banking77 test split. A separate cluster run processes 50 million simulated messages from one million users. Exploratory analysis shows overlapping intent language and distinct simulated session patterns. These results measure intent classification and distributed processing rather than fraud-detection performance.

1 Introduction and Background

1.1 Problem and motivation

Bank chatbots receive questions about payments, account access, transfers, and other services. Similar wording can occur in a routine request, a compromised account, or a conversation with a customer experiencing a scam. A useful review system therefore needs to consider both what a message says and the surrounding activity. This project develops the data and modeling workflow for that task.

1.2 Research question

How much does user behavior add to fraud detection beyond message text alone?

We investigate message intent and describe temporal, session, sequence, and geographic patterns in the simulated stream.

1.3 Background and label definitions

The source is PolyAI’s Banking77 dataset, used here following the course final-project framework. Banking77 is an intent-classification dataset, not a collection of verified fraud cases. We distinguish three labels throughout the report:

  • Intent: the customer request category supplied by Banking77.
  • Assigned risk and fraud type: our intent-level taxonomy for organizing review queues.
  • Simulated fraud: the message-level is_fraud flag assigned by the stream generator.

An intent such as an unrecognized card payment can be relevant to fraud review without proving that its author is committing fraud.

2 Data Sources and Pipeline

2.1 Banking77 source data

Banking77 contains 13,083 English customer messages: 10,003 training examples and 3,080 test examples across 77 intents. Each source row contains text and an intent label; observed user identities, session histories, times, cities, and fraud outcomes are absent. The dataset card lists a CC BY 4.0 license.

2.2 ETL and intent catalog

The preparation script validates source columns and split sizes, copies the input files, collapses whitespace, trims text, and rejects empty cleaned messages. It attaches intent names and preserves the original split, producing banking77_clean.parquet with text, label, intent, split, and text length.

A second table, dim_intent.parquet, contains one row per intent, including journey stage, assigned risk, fraud relevance, validity dates, and intent-set version. The taxonomy organizes 77 intents into 11 journey stages and marks 22 intents as fraud-relevant across six taxonomy groups. These groups differ from the five behavioral patterns introduced by simulation.

2.3 Simulated message stream

The generator uses seed 7 and samples wording from the training split. It adds users, sessions, timestamps, cities, and behavioral fraud flags. Approximately 30% of messages retain a manual intent label; the remaining messages enter an unlabeled scoring population. Eight percent of users are assigned a fraud persona, but only their designated fraud bursts receive a fraud flag.

Profile Messages Users Date window Use
Development 500,000 10,000 October 2026 Stream EDA and saved local intent scoring
Full 50,000,000 1,000,000 November 2025–October 2026 Recorded S3/Spark cluster processing

The five patterns are account takeover, money mule, card testing, location anomaly, and night activity. Ordinary sessions also include occasional nighttime activity, travel, and sensitive intents, so those individual attributes are not exclusive fraud indicators. Messages are written in chunks partitioned by date.

2.4 Storage and processing pipeline

Local preparation produces cleaned source tables and simulated Parquet files. The executed cluster notebook reads the simulated stream from Amazon S3, compacts its daily partitions, and writes intermediate session tables and small summaries back to storage. This demonstrates an S3 processing path even though the existing upload helper and central storage configuration remain placeholders; they are not a complete automated deployment workflow.

The ETL implementation is in src/data/prepare_banking77.py and src/data/simulate_stream.py, with parameters in config/.

The saved cluster analytics run and local intent-model run are separate execution paths. Full-stream distributed fraud-model training is not demonstrated.

3.2 Cluster configuration

The cluster notebook runs from an EC2 master using a three-worker standalone Spark cluster. Its recorded default parallelism is six cores. Configuration sets 48 SQL shuffle partitions, 4 GB executor memory, 2 GB driver memory, and the Hadoop AWS package for S3 access.

3.3 Partitioning and intermediate tables

The full stream initially contains 18,250 Parquet files. Repartitioning by date and rewriting the stream produces 365 files, with an assertion checking that the 50-million-row count is unchanged. Per-user lag windows calculate message gaps; session grouping produces message counts, durations, and city counts. Only small aggregate tables are collected into pandas for reporting.

3.4 Reproducibility

The repository stores simulation settings, notebooks, output CSV files, and cluster screenshots. This manuscript references those existing artifacts and has execution disabled, so rendering does not launch simulation or Spark jobs.

4 Exploratory Data Analysis

4.1 Intent structure and semantic overlap

Part A examines the original 13,083 messages. Assigned risk is concentrated in account-access and identity intents: 87.5% of account-access sentences and 74.5% of identity sentences are assigned high risk. These proportions describe the chosen taxonomy, not the prevalence of fraud in banking conversations.

The semantic map uses MiniLM sentence embeddings and UMAP. The original embedding space, rather than the two-dimensional plot, supplies the nearest-neighbor measurements. Identity-related wording remains cohesive across different intents, whereas apparent account-takeover cohesion is driven largely by neighbors of the same intent. This cautions against interpreting visual separation as a detector.

Median message lengths are 46 characters for low risk, 50 for medium risk, and 45 for high risk. Length alone provides little descriptive separation.

4.2 Text features and intent confusion

Part B fits a TF-IDF/logistic-regression intent baseline and examines its errors. Its held-out accuracy is 89.06%. Among 880 test messages assigned fraud-relevant intents, the analysis reports 56 routed to ordinary servicing categories. This is taxonomy-based routing error, not a count of confirmed fraud cases missed.

A keyword rule constructed from training text retrieves 678 of 880 fraud-relevant test messages: 77.05% recall with 28.79% precision. It flags 2,355 messages in total, illustrating the false-alert burden of treating characteristic words as standalone detection rules. Urgency analysis also finds that incident words such as references to theft are more informative for some taxonomy groups than generic time-pressure language.

4.3 Temporal and session behavior

Parts C and D visualize the development stream. Their patterns reflect the simulation rules. Ordinary sessions typically contain three messages and last six minutes. Development-stream card-testing sessions have a median of eleven messages over seventeen minutes; money-mule sessions span much longer intervals. These are descriptive contrasts rather than measured predictive performance.

The full-stream Spark analysis supports similar descriptive comparisons. Its median within-session message gap is 115 seconds for ordinary messages, 64 seconds for card testing, and 143 seconds for account takeover. Message speed therefore does not isolate every simulated fraud pattern.

4.4 Intent sequences and geography

Part D examines adjacent intent transitions within sessions, distance from the user’s simulated home city, and intent co-occurrence. Account-takeover sequences move from account-access topics toward transfers by construction. Location-anomaly bursts occur away from home, but ordinary trips also occur away from home, so distance alone is not equivalent to fraud.

For descriptive sequence analysis, missing intent labels are recovered through text lookup against the source catalog after consistency checks. This is not a demonstration of model accuracy on unseen wording.

4.5 Implications for modeling

The analyses motivate combining text with session size, duration, recent message gaps, intent transitions, and location history. They also reveal shortcuts a model might exploit. In the saved full-stream persona summary, location-anomaly users average about 23 messages while normal users average about 50; background volume therefore remains a potential confound. These features require evaluation on held-out users or time periods before they can support detection claims.

5 Natural Language Processing

5.1 Text preparation and TF-IDF

The scikit-learn baseline uses unigram/bigram TF-IDF with sublinear term frequency, Unicode accent stripping, and a minimum document frequency of two. The vectorizer is fitted on the original training split and transforms the held-out test split.

The Spark pipeline lowercases and tokenizes text, constructs bigrams, fits separate unigram and bigram count vocabularies with minimum document frequency two, applies IDF weights, and assembles the vectors. Its feature construction and regularization settings differ from the scikit-learn pipeline; the reported scores are separate baseline results rather than an isolated comparison of execution engines.

5.2 Sentence embeddings and semantic analysis

Part A uses all-MiniLM-L6-v2 to represent each message as a normalized 384-dimensional vector. Fifteen cosine nearest neighbors characterize semantic overlap, including an analysis excluding neighbors with the same intent. UMAP uses cosine distance, fifteen neighbors, minimum distance 0.1, and random seed 7 for visualization. These embeddings support EDA; they have not been evaluated as features in the planned fraud comparison.

6 Machine Learning

6.1 Tasks and evaluation design

The completed supervised task predicts one of 77 intents using the original 10,003/3,080 train/test split. The proposed fraud task instead predicts simulated is_fraud. Intent accuracy cannot substitute for fraud precision or recall. Repeated training sentences in the simulated stream also mean that scoring this stream is an operational demonstration rather than an independent generalization benchmark.

6.2 Intent classifiers

The scikit-learn model is logistic regression with C=10, up to 2,000 iterations, and random state 42. The Spark MLlib model is multinomial logistic regression with regParam=0.01, no elastic-net mixing, and up to 100 iterations. Its model is saved and reloaded before scoring unlabeled messages. Predictions include the assigned intent, taxonomy risk, probability-based confidence, and a review flag when confidence is below 0.5. That threshold is a review heuristic, not a calibrated fraud threshold.

The saved Spark intent notebook runs with ON_CLUSTER=False. It trains on the original Banking77 training split, not on the stream’s manually labeled subset; the stream is subsequently divided into labeled and unlabeled tables for scoring.

7.6 Scope of performance evidence

The repository demonstrates full-scale distributed analytics and a separate local intent-model run. It does not provide controlled scaling experiments, full-stream cluster intent inference, or measured single-machine memory failure.

8 Discussion and Conclusion

8.1 What the current results establish

Text models classify Banking77 intent with useful held-out accuracy, while the routing and keyword analyses identify overlap between ordinary and fraud-relevant wording. Spark processes the larger simulated stream and extracts compact behavioral summaries. These results establish the analysis foundation; they do not yet establish how much behavior adds to fraud detection.

8.2 Limitations and validity

Fraud labels are assigned by generator rules. Learning those rules successfully would not demonstrate performance on real bank fraud. User histories, cities, and times are synthetic; city-center distances are not verified impossible travel. Repeated source sentences limit linguistic diversity. Taxonomy-assigned risk differs from simulated message-level fraud, and false-alert rates measured against one definition should not be described using the other.

Some background-volume differences and time-window restrictions could provide artificial model shortcuts. The development EDA and full-scale analytics also cover different date windows and populations; their numbers should not be mixed. Probability confidence is not calibrated, and the review threshold has not been validated against review capacity or monetary costs.

8.3 Future work

8.4 Conclusion

The project has implemented data cleaning, a reproducible simulated message stream, text and behavioral EDA, intent classifiers, and S3/Spark processing of 50 million messages. The strongest completed predictive result is 89.06% intent accuracy on the held-out Banking77 test split.
